# 游戏反外挂：瞄准行为检测与工程扩展

首要目标：客户能判断哪些输入能支持检测、模型相比规则解决了什么、误报与性能代价是什么。第一版建立可复核的本地研究案例；不修改线上部署。

## 第一阶段计划

| 功能 | 内容与验收 | 状态 |
| --- | --- | --- |
| 数据与评估协议 | 审计 GAN-Aimbots ViZDoom 原始日志、来源许可、设备分组、采样与泄漏边界；冻结训练／校准／留出协议 | 已完成 |
| 检测训练与证据 | 规则、线性分类、LightGBM；条件允许增加时序网络。阈值只看校准集，保留漏检、误报、未见辅助类型与 CPU 成本 | 已完成 |
| 客户体验 | 输入轨迹、告警证据、同阈值目标对照、失败样本、完整统计折叠；案例／方法／教学／扩展四入口 | 已完成 |
| 工程扩展 | 微自瞄、透视、多模态、跨局信誉；数据契约、回放、监控、分级推理与容量验证计划 | 已完成 |

## 数据选择

- 作者：Anssi Kanervisto、Ville Hautamäki、Tomi Kinnunen。
- 官方归档：https://zenodo.org/records/6345323 （v2，CC BY 4.0；元数据已核实）。
- 论文：https://arxiv.org/abs/2205.07060 。只参考数据定义和防御评估，不运行或提供作弊生成器。
- 实验环境为 ViZDoom；标签表示采集时是否启用指定辅助，不能当作每次射击都有作弊动作的人工判定。
- 原始硬件标识只用于防泄漏分组，不进入模型、前端或 Git。不能将设备等同真实自然人。
- 更接近现代游戏的 CS2CD 与 XGuardian 留作后续；新游戏必须重新审计版本、标签、设备输入、武器、地图和切分。

## 必须区分的能力

1. 已运行：本地保存记录上的检测、解释、错误分析、单机 CPU 测量。
2. 未验证：真实竞技服迁移、端到端网络与排队、跨局信誉、多模态融合、透视检测、百万并发。
3. 防御实验：未见辅助类型评估与采集质量压力测试；不能称已抵抗所有 AI 外挂，不以公开测试反复调参选优。
4. 处置：输出复核线索，不自动封号。实战需经过安全策划、客户端／服务器、运营复核团队确认标签与处理阈值。

## 界面约定

沿用工坊蓝灰与青色、既有字体和导航。正文 16px，表格 15px，分节标题 22px；首屏先给检测任务、当前结论与误报代价。只将计算细节折叠，证据范围与未验证能力保持可见。

## 首次审计（2026-10-28）

归档 256 局、41 个硬件分组，提取 23,330 个不重叠的射击前一秒窗口。训练／校准／留出设备为 24／8／9，窗口为 13,980／5,237／4,113。留出 GAN group1 只有 61 个窗口，不能将此小样本结果当作广泛防绕过结论。组内辅助启用是弱粒度实验标签，不是逐射击人工证据。

## 首轮结果与后续顺序

运行 `vizdoom-aim-v1`。传统辅助的 1,880 条留出窗口：规则检出率 4.26%，逻辑回归 57.66%，LightGBM 58.62%，CNN 61.70%，加入 GAN A 的 LightGBM 59.04%。对应 1,872 条正常窗口误报率为 3.42%、4.01%、3.26%、3.31%、2.94%；均超过约 1% 的校准目标，不能直接扩大为生产处置阈值。

GAN B 只有 1 个留出设备／61 条窗口：基础 LightGBM 检出 39.34%，CNN 3.28%，增广 LightGBM 45.90%。不以单设备的退化 bootstrap 区间冒充跨设备稳定性。增加 GAN A 是已知攻击样本暴露实验，不是新生成攻击的对抗训练。

基础 LightGBM 单窗口计算 p95 为 0.128 ms；CNN 为 0.039 ms。单机预热串行 1 线程，包含模型所需特征／归一化，不含事件解析、窗口积累、网络、排队、并发。不得声称百万并发已验证。

一次多 OpenMP 运行库冲突导致的训练中止已保留于 `artifacts/anticheat-runs/vizdoom-aim-v1-aborted-openmp/`，在 CNN 拟合与留出评分前发生。保持数据、模型和种子不变，改为单线程后完成首次评分。留出已消耗；不能反复调参后称新盲测。

下一轮优先级：
1. **正常玩家保护**：增加正常设备、高水平玩家及版本覆盖；新校准／新留出中验证低误报阈值与多窗口复核规则。当前旧留出只能作为已知诊断。
2. **现代游戏迁移**：优先审计 CS2CD／XGuardian 的玩家身份、时间顺序与许可；新游戏单独实验，不混合当前成绩。
3. **射击与可见性证据**：引入可信射击事件、武器状态、目标相对运动；有合法信息渠道与遮挡真值后才做透视检测。
4. **工程验证**：先离线回放／影子服务，后压测；按请求速率、端到端延迟与复核容量验收，而不是直接使用在线人数作为模型吞吐。

## 使用与复现

- 原始归档下载到 `data/anticheat/raw/data.zip`，官方文件：https://zenodo.org/api/records/6345323/files/data.zip/content 。固定 MD5 见协议；当前已下载并验证。
- `npm run prepare:anticheat`：特征与设备审计；原始文件和硬件标识不入 Git。
- `npm run train:anticheat`：首次冻结训练；同版本存在时拒绝覆盖。
- `npm run verify:anticheat`：校验源文件、保存模型、全部分数、分组统计、样本与贡献；不重新训练。
- 入口 `#anticheat?case=vizdoom`，模型／教学／场景扩展沿用同一业务状态。默认公开构建隐藏入口并排除研究结果包；本轮没有发布线上。
