## 目标与验收原则

首要目标是帮助潜在客户判断是否值得委托：能否理解业务问题、把数据转为可用结果、设计可信的效果验证，并判断应用条件。次要目标是学生的学习；特征计算、实验控制与模型原理放在可展开的第二层。主任务是深入七个已建场景，不增加算法展厅、客户数据接入或在线训练平台。

### 第一性原理：从客户的判断倒推内容

客户购买的是解决问题的能力，不是模型名称或算法数量。公开案例无法证明某个客户会获得相同收益，因此展示可迁移的方法能力和证据链，不承诺业绩。

| 客户需要判断 | 必须提供的证据 | 不采用的替代品 |
|---|---|---|
| 是否理解我的问题 | 谁在何时做什么决策，输入和输出是什么，简单规则有哪些不足 | 一上来介绍算法结构 |
| 是否有实际改进 | 同输入、同范围的基线对照，整体增益与代价并列 | 只展示最好个例或高分大字 |
| 是否能解决难点 | 特征工程、阶段分解、受控实验和失败诊断与结果相连 | 堆砌模型名和训练日志 |
| 我的业务是否适用 | 必要字段、历史跨度、失效条件、冷启动与上线前验证要求 | 将公开基准直接当作客户效果 |
| 可以委托做什么 | 数据审计、模型、评估报告、批量结果或接口及交接文档；区分案例已实现与定制范围 | 假造客户项目与经营收益 |

默认阅读顺序：业务任务与同输入结果 → 整体证据 → 改进过程 → 适用条件与交付能力。公式、参数、逐条计算放在第二层。优先补最阻碍客户作判断的证据缺口，其次补教学材料；新实验先说明它能改变哪个方案选择，再确定模型和算力。不懂模型名的客户仍能说清输出、对照对象和结论适用范围，才算展示完成。

每个主案例采用同一条阅读路径：业务问题 → 同输入基线对照 → 整体与分组证据 → 特征／方法实验 → 失败诊断 → 适用条件。留在现有体验、数据、方法、报告中，不增加顶层菜单。先复用已核验的保存证据，只有问题需要且证据不足时才启动新实验。

- 同样本差异不是全体收益。改善／持平／退步同时可见，默认不按最好效果选例。
- 分母、样本数、时间窗口、指标方向、零分母与候选上限明确；不跨任务或数据版本计算提升。
- 事后失败分析不冒充预设独立检验；已消耗测试不能重新打开用于选模。
- 特征重要性、属性相似度、个例解释不是因果归因。证明某组输入有效需要控制候选、样本、参数和训练预算的消融。
- 成本模拟、分群画像、公开基准不写成客户经营收益。复杂模型不胜出时说明取舍，不更换指标掩盖失败。
- 每个功能独立 Git commit；数值计算测试、现有检查、桌面／手机验收后记录真实状态。

### E4 的两项功能与停止条件

1. **E4-A，预测前信息审计与冻结诊断协议。** 绑定 E3 父版本，逐字段记录可用日期、缺失与计算范围。先检查现有 56 天历史可计算的近／远期销量变化、零销量占比、历史波动，以及预测值相对历史尺度；业务价格、订单结构等只有保存证据且时间边界可核验时才纳入。用全部窗口检查信号，不能只为 2011-10-22 或某个失败商品挑规则。先冻结少量诊断定义，再连接已知结果；依然标为已知数据开发诊断，不称预注册独立验证。完成审计与校验后单独 commit。
2. **E4-B，客户可读的适用证据。** 在现有预测体验／报告中将当前商品的历史信号、模型／中位数的误差与区间代价、同范围统计连起来；提供“失败前有变化”“未发现可用变化”“样本不足”这类有依据的说明，不以颜色灯号假装校准概率。分组给出人数／窗口数，展示误警与漏识别；公式和完整明细折叠，原 E3 区间不重调。完成计算测试、静态页面和桌面／手机验收后单独 commit。

E4 不保证找到可提前预警的信号。若现有字段不能解释尖峰，交付明确的“现有输入不足”结论，并列出促销、库存可售、批发大单等**待核实输入**及其在预测时是否可知；不把这些假设写成真实成因。分组只说明历史关联，不能证明未来自动切换模型有效；未通过新的验证前仍是人工复核建议。无须新增模型、API、客户数据上传或调优平台。

1. **分群优先**：先补商品偏好特征与同特征 K-means 对照，再做 Leiden／HDBSCAN；解释从价值分层到偏好社群的变化。
2. **推荐与检索**：分别核查序列数据条件、实现 ColBERT 小规模离线可行性与成本分析，再决定正式训练／评估。

4. **分类与决策**：按类别字段、复核预算、风险偏好和库存状态的具体业务需求升级；无需为完整名单统一训练深网。

### 模型升级第一轮：商品偏好分群（2026-10-14，已实施）

本轮沿用“先分群、再推荐与检索”的顺序，只完成一个业务的升级，不同时铺开七类训练。新增独立实验 `preferences-20261014T104453501853Z`，原 R5 分群、PCA、跨月固定中心分析和冻结指标保留。训练功能提交 `10fe10a`。

- **输入与表示**：同源 UCI 正向交易，两期前 180 天，首期确定 2,480 件商品目录、TF-IDF、32 维 SVD；非零次数使用 `1+ln(n)`，不是 `ln(1+n)`。RFM 不进入偏好特征。两期 2,768／2,919 位顾客均有可用特征。SVD 保留变异 14.86%，明确展示压缩信息损失。
- **真实方法对照**：偏好 K-means 四群、Leiden、与 Leiden 同群数 K-means、HDBSCAN，并保留原 RFM 归组。避免把特征更换、群数变多和算法本身的增益混为一谈。
- **面向客户的展示**：在原“零售分群”中切换商品偏好／RFM 目标；具体顾客的真实购买商品、图邻居／中心距离／密度归属强度；同价值层、不同偏好顾客配对；代表商品人数占比与价值层交叉画像。模型、教学、报告链接保留目标、时点和选择，没有新增菜单。
- **评价边界**：已知公开数据开发诊断，非新的独立测试。历史代表商品与分群先冻结，再附加后 30 天实际购买；重合率包含全部未来商品分母，不是推荐成绩、聚类准确率或营销收益。

| 观察起点 | Leiden 群数 | Leiden 后续商品重合 | 同群数 K-means 重合 | HDBSCAN 已归群／全体 | 未归群 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2011-09-01 | 22 | 9.66% | 10.25% | 514／2,768 | 81.43% |
| 2011-10-01 | 21 | 7.31% | 7.32% | 486／2,919 | 83.35% |

两方法重合率分别基于相同的 903／900 位后续回访顾客。HDBSCAN 仅对 157／137 位已归群回访顾客计算重合，报告列明排除人群，不跨行直接排名。偏好 K-means 四群的重合为 5.64%／4.59%，原 RFM 四群为 3.79%／3.41%；这是偏好特征在本诊断的用途，不否定 RFM 价值分层。

结论：偏好分析补出了 RFM 没有表达的商品关系；Leiden 未超过同群数 K-means。HDBSCAN 当前参数只适合研究少数核心群，不适合作为全量客群分配。报告保留建图、分辨率、密度参数、种子、80% 抽样与跨月重拟合敏感性；没有用后续结果重新挑参数。

后续顺序：
1. 已完成本轮分群。文本、价格特征消融及稳定的新客分配另行规划，不将当前未归群顾客强行命名。
2. 下一轮审查推荐序列数据是否足以支持 SASRec，并完成检索 ColBERT 的小规模可行性、许可和成本分析；审查后决定是否正式训练，不承诺模型必然更优。
3. 预测／异常、分类／决策继续按上表的数据条件推进。

验收：147 项前端测试、84 项基础 Python 测试、5 项偏好实验测试、语法检查和公开构建通过。构建校验偏好文件哈希、原 RFM 版本绑定、画像分母和后续重合率。桌面与 390×844 手机核对体验、数据、模型、教学与报告，无整页横向溢出；核验时点切换、HDBSCAN 未归群、原 RFM 切换、顾客配对跳转及刷新恢复。浏览器未记录脚本错误。新结果为静态回放，无本地模型 API 依赖。

**实施条件与后续小实验**：

#### ColBERT：CPU 可运行，长摘要和多向量成本是前置问题

固定官方权重 `colbert-ir/colbertv2.0@c1e84128e85ef755c096a95bdb06b47793b13acf`；协议 `services/feasibility/colbert-protocol.json`。5,183 文献与 300 查询文本来自原冻结 SciFact 产物并核验哈希，未读取 qrels 或重新评分。按 ID 哈希预选 256 文献／12 查询，4 CPU 线程、batch=4；先预热，查询计时 3 次。源码、权重文件哈希和环境记录在 `docs/evaluation/colbert-feasibility-v1.json`。

| 核查项 | 本轮结果 | 对展示与实施的含义 |
| --- | --- | --- |
| 权重／基本匹配 | 官方 BERT＋128 维投影、未压缩 MaxSim 原型跑通 | 尚未验收官方 PLAID／压缩引擎，也未核对官方引擎逐分数一致性 |

**下一阶段实施优先级**：
1. 先核对官方引擎与原型的 token、mask 和逐分数一致性，准备固定的长摘要／长查询分组及分块规则。
2. 在现有融合 Top 50 上对照交叉编码器与 ColBERT；这只检验重排，不能宣称召回提升。另开全库多向量召回实验，报告与原 BM25／MiniLM 的候选覆盖与组合增益。
3. 同一候选池、同一文本分块下比较方法；另做分块贡献对照，保留原未改动基线，避免把文本覆盖增益全算给模型。多块汇总规则与长文长度偏差须在评分前固定。
4. 先冻结全量排名和成本，再用现有已知公开标签作开发评估；报告长摘要、长查询、原有遗漏与排名退步。禁止将当前 300 查询转为训练样本后再称独立验证。
5. 展示查询词与文献片段的真实匹配、未命中证据、索引体积和延迟。是否进一步使用压缩引擎或 AutoDL，以全库实测与微调需要决定。
