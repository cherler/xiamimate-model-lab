# 案例体验：潜在客户视角分析报告

日期：2026-10-14。对象是首次访问模型工坊、正在判断“能否委托解决类似问题”的潜在客户；学生是第二受众。本报告核对了七个公开案例的实际体验页、现有讲解提纲与冻结证据。1280×720 的首屏位置是一次桌面页面检查，不代表所有设备。没有进行真实访客访谈、理解度或转化测试。

## 总体判断

七个案例已能证明一项关键能力：从业务输入构造模型或规则，在同一评价范围与简单方法比较，保留退步、成本、数据条件和未验证结论。客户可以沿“样本结果 → 全体报告 → 适用条件”追溯证据。这比继续增加算法名称或案例数量更有说服力。

当前最大阻碍是**判断所需信息出现得太晚、分散在多处**。客户进入“案例体验”后，先读导读、选项和方法说明，再滚动到结果，随后跳报告核对整体，最后返回条件说明。推荐和预测页的案例标题在检查视口约第 681 像素处，主要样本与整体比较还在下方；决策优化页的首个“预测与策略的贡献对照”标题约第 962 像素处。若访客只看首屏，很可能尚未看到结果。各场景的信息顺序也不一致：推荐／预测先显示导读，分类等案例先显示标题。以上是页面可见性观察，不是用户行为数据。

建议把每例首屏收束为同一张“客户判断卡”：**要解决的问题、输入与输出、同范围对照结论、代价或退步、证据性质、需要的业务条件**，并用一键入口下钻到样本、完整报告和模型方法。卡片直接读取现有冻结报告，不能人工复制一套会随版本失效的成绩；当前选择改变时，卡片要么同步更新，要么明确标为固定全体结果。不得用一个成功样本替代总体结论。

## 七例逐项判断

| 案例 | 客户能看到的能力 | 当前最可能留下的疑问 | 优先补强的展示 |
| --- | --- | --- | --- |
| 商品推荐（公开 Ta Feng） | 历史购买到复购／发现名单，同顾客方法对照，复购通过预设筛选，发现未通过 | 编码商品即使配有频次和时间，也不容易形成“推荐了什么”的直观印象；条件 Recall 容易被当作全购物篮覆盖 | 首屏先解释复购范围与总体筛选结论；给商品卡增加已核实的类别／行为说明，不造名称；紧邻说明“新商品发现未过关”和全篮子范围 |
| 销量预测（公开 UCI） | 同商品周的七日总量预测、强基线、误差与窗口稳定性 | 访客可能把记录销量当实际需求，把周预测当逐日采购建议；开发回放容易被当独立测试 | 首屏并列基线和模型的全体 WAPE／偏差／胜出窗口，显式标“历史开发验证”；给出一条高误差商品周的入口 |
| 分类与评分 | 同邮件判定、纠正／新增错误、复核名额和假设成本取舍 | 漏报大幅减少的同时，复核量和误报增加；客户需要知道何时选规则、何时选模型 | 默认展示一行“少漏多少／多审多少／多误多少”，成本仅标假设；新邮箱适用性另列 |
| 智能检索 | 关键词、向量、融合和重排各阶段的文献位置，可核对遗漏与耗时 | 重排收益很小但计算代价大；未标注文献不能直接判无关 | 首屏用“相关文献进入了哪一层、质量变化、耗时变化”说明是否值得重排，并显示候选外无法挽回的数量 |
| 异常检测 | 同一事件的首报、重复、抑制与未报，跨序列方法差异 | 哪种方法适合自己的监控对象？事件窗口命中能否代表真实故障发现？ | 按设备／环境／负载并排呈现检测事件与窗口外告警，明确每序列事件数很少、真实处置未验证 |
| 零售分群 | 同顾客双方法画像、群体交叉、重拟合稳定性与跨月迁移 | 群的含义和可以采取的行动是什么？分群是否带来收益？ | 将“可支持的运营判断”与“须通过触达实验验证的收益”并列；不把轮廓分数写成准确率 |
| 决策优化 | 预测进入预算、库容和整包约束，订单与费用可逐商品核算 | 场景目标变好、事后模拟成本却变差；客户会问优化价值何在 | 把这个反转作为首屏结论，并直接说明其揭示了需求场景和成本假设的风险；保留模拟性质，不写成真实利润 |

本地研究的 Dressipi 与 M5 可用于讲解更丰富的推荐和预测思路，但默认公开构建排除其结果。对外公开路径的主证据分别是 Ta Feng 与 UCI；不可把本地研究的数字混入公开案例，也不应为了“赢”而隐藏简单基线胜出的结果。

## 优先级与验收

1. **P0｜统一首屏判断卡。** 七例在 1280×720 桌面视口和常见手机宽度下，访客不用先操作筛选器就能看到任务、一个同范围效果结论和证据性质；数值与原报告一致。推荐／预测恢复标题优先于导读的层次。复杂控制和计算放在下一层。
2. **P1｜压缩跨页阅读成本。** 体验页的全体结论分别直达对应报告段落，报告返回当前案例与筛选状态；“个例表现”和“总体表现”有固定标签。用已有 11 个案例变体逐一检查链接，不新增结果口径。
3. **P1｜把失败与适用条件写成业务选择。** 每例至少回答“何时先用简单方法、何时值得用模型、哪些数据缺失就无法下结论”；异常检测和检索尤其要把复杂方法的代价放在增益旁边。
4. **P2｜做真实客户理解度测试。** 找 3–5 名未参与开发的人，每人随机看 2 例，记录是否能在约三分钟内复述输入、输出、基线、增益或退步、必要数据与不能承诺的效果。现有 D8 三分钟提纲只是设计目标，不能当作测试通过记录。

不建议下一轮继续扩展案例数。先让七例从首屏就能回答委托判断，再补真实访客反馈；新训练只应针对能改变方案选择的明确证据缺口。
