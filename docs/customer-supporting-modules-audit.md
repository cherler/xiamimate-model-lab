# 模型解读、教学拆解、交付方式：潜在客户视角分析报告

日期：2026-10-14。检查对象是本地运行页面及其现有文案；推断的是首次访客可能遇到的理解与转化障碍，不是已测得的访客行为。首要目标是让潜在客户看懂建模与交付能力，学生学习居第二位。

## 模型解读

**现状。** 页面以“推荐与预测模型说明”为标题，列出复购、商品发现、UCI 推荐和销量预测模型；每个方法可看输入、处理、输出、特征、限制及已运行的指标。特征使用表诚实区分“已使用／部分使用／未使用”，也保留复杂模型没有胜出的事实。这对懂技术的访客有可信度。

**客户障碍。** 顶部导航叫“模型解读”，左侧却有七类业务，进入独立页面只见推荐与预测。分类、检索、异常、分群、优化虽然各自案例内部有“方法”层，但访客没有统一索引，容易误判后五类只有演示而没有建模解释。当前默认进入 ALS＋衰减复购，先读算法细节，再读业务收益；这与客户决策顺序相反。页面下方的进阶实验链接使用旧的 `#advanced`、`#automl` 路由，虽有兼容，仍会使上下文跳转不够清晰。

**建议。** 先把独立页改成七场景“方法选择入口”：每类只展示业务任务、简单基线、当前方法、实际取舍、数据要求，点击进入原案例的“方法与约束／效果报告”。推荐与预测保留现有详细模型卡，改为展开层。不要另造七份模型说明或复制指标。每张卡必须能回答“为什么没有只用最复杂的模型”；例如分类的少漏报与多复核、检索的微小质量增益与耗时、优化的场景目标与事后反转。研究限定结果与公开可展示结果分开。

**验收。** 从模型解读可抵达七个公开案例各自的方法和同范围证据；任一方法名都能回到它服务的业务任务；没有跨任务比较分数或把模型分数写成业务概率。

## 教学拆解

**现状。** 独立页用 Ta Feng 的保存列表和预测逐行复算 Recall、NDCG、WAPE、MAE、偏差，明确样本指标与全体指标不同；内容严谨，适合正式教学。其他五类已有各案例内部的“计算与实验阅读”展开入口，UCI 建模方法也有课程链接。

**客户障碍。** 顶部“教学拆解”是一个与案例体验并列的主导航，独立页却只给推荐和预测两门指标课，容易让客户以为其他五类无法教学或解释。首屏直接进入样本选择、K 和公式，对潜在客户来说信息密度高，且与其“能交付什么”没有直接连接。Ta Feng 商品多为编号，教学计算可成立，但不适合作为商品语义能力展示。

**建议。** 让该页承担课程目录而非扩充七套长篇公式：先给“七场景各学会哪一个判断”的卡片，并链接到现有真实记录计算；Ta Feng 推荐／预测保留为两门完整示范课。每课开头用一条业务问题和一条结论说明为何要算，再进入公式。对客户只提供“验证过程可复核”的证明，学生可继续展开逐条计算和实验记录。避免在客户主路径自动展开教学层。

**验收。** 七场景均能从课程目录到达对应计算入口，返回原案例报告；每门课标明数据、分母或时间范围、一个失败条件；默认客户路径不会先出现整页公式。

## 交付方式

**现状。** 页面已把服务分成数据可行性、模型原型、业务接入与教学，且逐一说明七类案例可讨论的能力与尚未验证的效果。推荐本地接口示例确实是已实现的一种接口形态。页面也明示项目独立、没有主站接入、没有客户数据或在线联系渠道。

**客户障碍。** “定制类似系统／整理我的需求”按钮打开的表单只下载一份本地 TXT；表单明确写着不会上传。这保护了数据，却也意味着客户填完后没有联系到任何人。若客户把按钮理解为询价入口，流程在下载处终止。三个服务层级描述的是工作内容，尚不足以让客户判断每一阶段拿到什么、如何验收、什么不包含；“业务接入与教学”把采购方和学员需求并在一张卡上。单个推荐 API 示例与七场景的广度并置，若未说明“仅是推荐示例”，也可能让人误认为七类都已有在线接口。

**建议。** 先将“整理需求”准确命名为“下载需求清单”，避免误认为已提交；在页面显眼位置给出一个真实、由站点所有者确认的业务联系渠道，或明确暂不接洽，不需要接入客户数据。把服务路径写成“讨论输入与验收 → 数据可行性结论 → 离线原型与评估 → 若需要再谈接入”，每一步列 1–2 个可见交付样例及验收依据，并区分本站已有示例与未来定制范围。教学辅导独立为轻量链接或说明。接口示例标注只覆盖当前本地推荐演示；其他场景以批量结果或页面回放为当前证据，不预售未实现接口。

**验收。** 第一次访问者能回答：本站已经做出的是什么、自己的项目需提供哪些最低条件、第一阶段会收到什么、如何联系或为何当前无法联系。需求清单不会被误认为已发送，页面没有客户数据上传能力，也不承诺公开数据成绩在新业务上复现。

## 建议实施次序

| 优先级 | 改动 | 原因 |
| --- | --- | --- |
| P0 | 纠正“整理需求”的动作含义，并在确认商务渠道后给出明确下一步；同时界定 API 示例范围 | 这是当前最直接的委托流程断点和能力范围误解 |
| P1 | 模型解读做成七场景方法索引，保留原有推荐／预测详情 | 修复导航承诺与内容范围不一致，让证据链闭合 |
| P2 | 教学拆解做成七场景复算目录，详细课程留在第二层 | 支持学员，也让客户看到结果可复核，但不抢客户主路径 |

三项均是内容结构与说明方式的改进，不需要客户数据接入、在线训练或新增算法。完成后用非开发者按“案例 → 方法 → 证据 → 交付”走查，再据实际反馈调整。
