# 固定评估协议 · Ta Feng v1

2026-10-12，阶段 2。机器配置：`services/configs/evaluation-v1.json`。本协议在模型开发和最终测试评分之前冻结；本次仅准备数据、核查结构、划分时间和建立读取约束，没有训练模型或计算测试指标。

## 1. 原案例的数据使用审计

UCI Online Retail II 原数据截止 2011-12-09 12:50。末日可能不完整，按既有口径排除。第一轮已经评估 10 月推荐和 10—11 月预测，第二、三轮进一步将 9／10／11 月用于选参及比较，推荐标签窗口一直到 2011-12-01 之前。

按项目共享数据的保守边界，12 月只余 1—8 日共 8 个完整日，能组成一个不重叠的 7 天窗口，没有完整自然月，也不足以验证时间稳定性。11 月 29—30 日虽然不在原逐日预测主表中，却属于已使用的推荐标签月，不能冒充全项目未见数据。

处理决定：UCI 的旧成绩和数据保留为开发验证案例；不事后把过去的训练期改名为独立测试，也不把短尾期包装成充分证据。完整本地实验列表、边界和文件哈希由 `scripts/prepare-evaluation.py` 写入 `data-readiness.json`。不完整实验目录也列入审计，不能因缺报告认定其数据从未被用过。

## 2. 新数据及选择理由

采用 [Ta Feng Grocery Dataset](https://www.kaggle.com/datasets/chiranjivdas09/ta-feng-grocery-dataset)，Kaggle 发布者 chiranjivdas09，版本 1，发布端 API 标注 **CC0: Public Domain**。版本、原始 ZIP、元数据响应均记录 SHA-256。授权判断依据是分发者声明；未声称另行核验了原零售商权利链。数据下载和转换留在本地，尚未对外发布新案例。

它包含 2000 年 11 月至 2001 年 2 月的商品交易，可在同一零售场景定义三个任务；选择依据是任务匹配与可预留时间，并未查看模型成绩后挑选数据。日期按源数据本地日历处理，未声明时区，不推测日内订单顺序。

筛选时核查过 [Retailrocket 发布页](https://www.kaggle.com/retailrocket/ecommerce-dataset/home)，其标注 CC BY-NC-SA 4.0，因此没有接入面向接单的展示；也不以某个分析代码仓库的开源许可替代数据许可。[UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset) 可作未来预测扩展，但与零售备货不同，本轮未下载或混入。

## 3. 固定时间与信息可用性

所有区间左闭右开。

| 用途 | 时间 | 允许的操作 |
| --- | --- | --- |
| 初始训练 | 2000-11-01 至 2001-01-01 | 清洗规则、商品入选、特征设计和模型拟合 |
| 开发验证 | 2001-01-01 至 2001-02-01 | 比较候选、选择基线／参数、诊断失败。可以重复实验，但保留日志 |
| 最终测试 | 2001-02-01 至 2001-03-01 | 开发结论全部冻结后一次性评估；不得用于选模型、阈值、商品、特征或校准 |

推荐固定 1 月 1 日开发起点、2 月 1 日测试起点，每次使用此前历史预测下一自然月第一购物日的篮子，窗口内不更新历史。

预测开发起点固定 1 月 1／8／15／22 日，测试起点固定 2 月 1／8／15／22 日，每次输出未来完整 7 天，共四个不重叠周。1 月 29—31 日不进入开发评分，但最终训练可按时间读取它们。最终测试采取预先规定的每周重训：后一个测试起点可使用已经发生的前一周销量，参数和处理规则保持不变；完整四周预测由程序连续生成，全部完成后才向开发者展示任何测试成绩。这是滚动预测测试，不是整月一次冻结参数估计值的预测。

训练样本完整标签的结束时间必须不晚于起点：7 天样本的 `label_end_exclusive <= origin`。历史特征只能读取 `< origin` 的数据。预处理器、缺失处理、商品属性、归一化和价格也遵守此界线，不能用全量数据计算。

本次自动清洗接触全量文件，但只输出测试分区的日期、行数、日期覆盖和哈希；不输出测试销量分布、用户偏好、商品排名、样例行或模型成绩。封存表示“未用于本项目开发决策”，并不意味着这个公开基准在世界上从未被研究。

## 4. 数据处理与商品范围

- 保留有效日期、商品 ID、正数数量与正数销售价格的行；异常记录数量进入审计。缺顾客 ID 可保留用于销量，推荐时排除。
- 没有订单号，不能证明相同行是采集重复，因此保留完全相同行的销量。推荐事件按“顾客＋日期＋商品”去重，篮子按“顾客＋日期”聚合；频次指购买天数，不称订单次数。
- 年龄、邮编、成本不进入模型；销售价格仅用于正向销售行的筛选。本版本不使用价格作为预测特征。
- 商品类别需要取起点之前最后已知值；未见类别为未知。不得从未来行补齐历史属性。
- 预测固定选择训练两个月中至少 14 个活跃销售日的前 50 件商品，按训练总数量降序、货号字典序处理并列。名单一次冻结；未来没有成交或表现差的商品也保留。
- 商品日缺行填零属于明确假设；如果整份源数据缺某天，准备脚本中止以待检查，不静默宣称日期完整。不因极端销量而删除或截断测试标签。

## 5. 两个推荐任务的评分

完整候选目录为起点前至少两名不同顾客购买的全部商品，不抽样负例。顾客历史集合包括全部历史购买商品，即使某商品没有进入候选目录。复购候选为目录与历史的交集，目标为下一篮子与历史的交集；发现候选为目录减历史，目标为下一篮子减历史。

两个任务分别排序、分别训练／验证。K 固定 10，无探索；候选少于 10 时不跨任务补满，报告不足比例。排序分数相同按货号字典序。目标中不在候选目录的商品仍留在分母和理想排序分母中，视为未命中，不根据测试商品修改目录。

主要人群是具有训练购买记录且在标签月再次购物的顾客。主指标为该人群平均 **NDCG@10**，对应任务目标为空时记 0；同时报告空目标占比。Recall@10 仅在任务目标非空者中求均值，清楚列出分母人数。Precision@10 的分母固定 10，另外报告命中率、覆盖率、未知目标比例、候选不足和冷启动。新顾客的发现任务用热门回退并单列，复购标为不适用，不与老客主表混合。

复购必备基线：个人购买天数频次、最近购买、90 天衰减频次。发现必备基线：排除已购的热门、ItemCF、ALS。候选模型和最强基线均按开发期主指标选定，测试时不重新挑赢家。精确同分时选择更简单者，再按模型 ID 排序。

项目预设增益筛选：相对开发期选定的最强基线，测试 NDCG 至少增加 0.01，且按顾客配对 bootstrap（2,000 次，种子 42）的差值 95% 区间下界大于 0。顾客为抽样单位，候选与基线共用抽样索引。两个任务分别报告，不事后选择其中最好的一项代表整个系统。该区间只表达这个月顾客抽样的不确定性，不证明季节稳定或收入因果收益。

## 6. 一周销量评分

目标是 50 件固定商品的未来完整 7 天记录销量，共 200 个商品周。最低历史窗口固定 28 天，使两个月初始历史能生成完整训练标签；不直接沿用第三轮的 56 天样本起点。

必备基线为全零、上周总量、近四周周均值／中位数和 AutoETS。最强非零基线只在开发期按 WAPE 选定。候选先要求开发期绝对总量偏差 ≤20%，再选择其中 WAPE 最低者；无人满足时报告没有合格候选，不默默放宽门槛。

主指标 WAPE = 全部商品周绝对误差之和／实际销量之和。辅助报告 MAE（件／商品周）、总量偏差、逐商品和逐周结果。分组实际总量为零时 WAPE 与偏差为空，同时给出绝对误差。总量偏差不能被较好的 WAPE 掩盖。

项目预设增益筛选：相对开发期选定的最强非零基线，测试 WAPE 相对降低至少 10%，绝对总量偏差 ≤20%，并在至少 3／4 个周窗口胜出。窗口严格比较 WAPE，相等不算胜。测试期间失败和回退必须记录；不删失败商品或窗口来达到门槛。这些是实验筛选条件，不是客户生产验收承诺。

四个周窗口不足以支持稳健的时间显著性结论，200 个商品周也不是 200 个独立时间样本。本版本展示所有周的误差，不借逐行 bootstrap 制造精确的时间置信区间。预测区间不在当前点预测协议中；未来若加入，必须在开启测试前另行固定仅使用开发数据的校准方案。

## 7. 冻结、单次测试和失败处理

1. `prepare:evaluation` 创建开发文件、独立测试文件、固定商品名单、结构审计与哈希清单；重复执行只验证已有文件，不覆盖它们。
2. 后续训练统一通过 `load_development` 读取，起点越过 2 月 1 日会被拒绝；每个样本检查标签结束边界。
3. 开发完成后生成一个 release 清单，固定三个任务的选定模型、全部参数、特征、开发期最强基线、开发成绩文件，以及训练／评分源码和依赖哈希。没有合格候选的任务应明确发布基线作为选择，并记录未达标原因；不能省略整个任务。
4. 未来最终评分器调用 `open_final_test` 前核对冻结文件，独占创建访问记录后才读取测试分区。第二次读取被拒绝；打开后的程序错误也消耗这份测试集，不可删除记录再调参。
5. 如发现实现错误，保留首次报告和错误说明。可作标明污染状态的修正复算，但不能重新称独立测试；新的独立主张需要新时期或新数据。

这些是可审计的本地流程约束，不是权限隔离系统；持有原始公开 ZIP 的开发者仍可绕过它们。本项目不会宣称测试文件物理不可访问。本次未调用测试读取函数，也未生成 release 或最终成绩。

现有第一至三轮训练入口仍用于 UCI，不能将新的分区文件随意代入旧脚本后称符合本协议。下一轮需实现 Ta Feng 数据适配及三个任务的评估器，并在开发区完成回放和边界测试后才制作 release。

## 8. 验收与修改规则

运行 `npm run verify:evaluation` 校验冻结文件和测试开启状态。测试使用人工小样本验证越界、哈希变更、缺开发决策和重复读取会失败，不使用真实封存标签来测试代码。

在最终测试未打开时，可以因明确的工程错误建立新协议版本，保留旧版、变更理由和日期。任何边界、数据、候选目录、指标或门槛修改都不得静默覆盖 v1。模型参数可在既定开发区选择，最后写入 release；这是有意允许的开发过程，并非所有超参数已在本阶段选定。

完成本阶段意味着有可执行的数据边界和评估规格，不等于已经证明模型有效。页面当前仍为 UCI 第三轮；最终验收状态是“Ta Feng 已准备，三个任务待训练、待独立测试”。
