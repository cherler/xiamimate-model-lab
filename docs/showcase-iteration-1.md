# 展示接入第一轮

2026-10-12，完成上线规划 L01–L03。默认案例改为 Ta Feng 的保存结果回放，UCI 第三轮通过案例选择保留。没有重训真实数据、修改既有模型成绩或重新读取封存测试源数据。

## 实现

- 导出器 `scripts/export-showcase.py` 核验两份固定实验的文件哈希；对 Ta Feng 全部已存推荐行复算任务规则、NDCG、条件 Recall、Precision、命中率和分群汇总，复算全部商品周预测统计。UCI 导出已有报告、序列和诊断，原交互仍由本地 API 提供。
- 案例清单包含任务、证据级别、实验编号、指标定义、原报告哈希与导出文件哈希。输出采用固定目录，重复导出必须一致；只有完整导出成功才更新清单。原实验与 UCI 最新指针不变。
- Ta Feng 推荐分为复购、未购商品发现，各有 4 种最终测试已评估方法。左侧为预测前的历史，中间为已保存 Top 10，右侧为下一购物日中属于本任务的真实目标。样本指标与完整人群指标分别展示。
- 固定哈希抽取 24 名训练顾客，其中本次 8 人有测试月记录，16 人未回访；未回访者保留并显示无可评分输出。另从实际冷启动人群按哈希抽取 3 名顾客，明确为测试后人群示例。没有按效果选出“最好看的顾客”。
- 周预测提供全部 50 件商品、4 个起点、6 种方法，总计 200 个商品周；图表展示起点之前四个周总量、当前七天预测与实际总量。零销量保留，相对误差不定义时明确说明。
- 展示冻结模型、冻结基线、全部其他已评估方法、筛选结论与推荐差值区间；发现和预测的失败结果保留。报告和全部商品周预测可以下载。
- 构建前校验完整展示清单；Ta Feng 前端读取时再次核验资源哈希和实验编号。原 UCI 接口必须与清单中的固定实验一致，否则报错。

## 设计

沿用原页面的冷白 `#F7FAFC`、海军蓝 `#17324D`、湖蓝 `#087FA0`、灰蓝 `#9BBCC8`、命中绿 `#DDEEE6` 与实际销量金色 `#9B7324`。继续使用系统中文字体，字号层级与原站一致。推荐采用历史、排序、真实目标三列；手机顺序堆叠。预测用有清晰时间边界的周总量柱图；完整比较放在下方，保持左对齐和数值对齐。

视觉重点是“推荐是否实际命中”和“预测与实际差多少”；不以装饰卡片或虚构商品素材代替证据。

## 操作

已有固定原实验时：

```sh
npm run export:showcase
npm run dev
```

案例入口：`http://127.0.0.1:5328/#recommend?case=tafeng`。切换目录可回到 UCI。`npm run build` 打包当前前端与展示资源，但全站独立静态发布仍未完成：Ta Feng 已能直接读取静态结果，UCI 原有推荐规则交互仍需要本地 API。

生成目录 `apps/web/showcase/` 忽略 Git，不能只复制源码而遗漏展示包。新环境需恢复固定实验后导出，或移交已导出的展示包；不通过重开最终测试补齐资源。
