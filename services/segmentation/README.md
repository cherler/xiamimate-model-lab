# Preference segmentation development study

Run `npm run train:preferences`, verify/export with `npm run verify:preferences`, and test using `npm run test:preferences`. This isolated CPU environment preserves the R5 model, assignments, metrics and lockfiles. No customer-data ingestion.

`protocol.json` is fixed before fitting. Source is the checksum-bound UCI cleaned cache used by R5 (all countries, positive transactions, known customers), 180-day history before September and October 2011. Catalog support, TF-IDF and 32-dimensional SVD fit only at the first origin. Each observation period refits preference clusterers; second-origin results are not frozen-center migration. RFM comes from the original frozen R5 groups. Customers without represented history are explicitly excluded, with IDs/counts retained.

Compare RFM K-means groups, preference K-means K=4, positive-cosine kNN Leiden, preference K-means with the primary Leiden group count, and HDBSCAN on exactly the same normalized SVD features. RFM is a separate feature contrast, not an alternative preference algorithm. Parameter probes and 80% resampling are predeclared and never select a winner from future purchases; sampling holds feature representation fixed. HDBSCAN noise remains in population denominators; silhouette is assigned-only with sample count and coverage shown, not directly comparable to full-coverage scores. ARI including noise and jointly assigned ARI are separate.

Historical customer prevalence determines each group's top-10 representative products. Freeze these and assignments before attaching 30-day future purchases. Future profile overlap compares group top-10 to global top-10 for the same assigned returning customers, keeping all future products in recall denominators, including unseen/outside-catalog products. It is a diagnostic of preference continuation, not personalized recommendation accuracy or causal campaign uplift. UCI outcomes informed prior development; no fresh independent-test claim.

Initial run `preferences-20261014T104453501853Z`: 2,768 / 2,919 customers, catalog 2,480, no zero-feature exclusions. Leiden 22 / 21 communities; matched-count K-means has slightly higher silhouette and future profile overlap in both windows. HDBSCAN assigns only 514 / 486 customers (7 / 8 groups), leaving 81.43% / 83.35% unassigned. Do not promote its assigned-only silhouette as the best all-customer partition. Parameter sensitivity is material and is preserved. SVD retains 14.86% of TF-IDF feature variance; compact representation may lose important distinctions.

Artifacts contain protocol/source/lock snapshots, source hashes, fitted transformations/models, customer features, purchase matrices, graph edges, frozen assignments, full diagnostics and checksums. JSON outputs are static and ignored by Git. Source: Chen, D. (2012), Online Retail II, UCI, DOI 10.24432/C5CG6D, CC BY 4.0; attribution accompanies exports.
